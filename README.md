# Network Log Analyzer Agent

An AI agent that reads network device logs, detects anomalies, and explains the likely root cause and fix in simple language. Built with Python, the Groq API (tool calling) and Streamlit.

The agent does not guess. The LLM decides which tool to call (parse logs, detect anomalies, check device status, ping a host), reads the real result, and only then writes its answer.

---

## Features

- **Autonomous tool use:** the LLM picks the right tool for each question (function calling).
- **Anomaly detection:** link flapping, low optical power, high latency and packet loss.
- **Root cause and fix suggestions:** plain-language explanation for each issue.
- **Chat UI:** Streamlit interface with conversation memory.
- **Transparent reasoning:** every tool call and its raw result is shown in an expandable panel.

## Tools

| Tool | What it does |
|------|--------------|
| `parse_logs(severity, device, limit)` | Filters logs and returns severity counts plus the latest events |
| `find_anomalies()` | Scans all logs for link flapping, low optical power, high latency, packet loss |
| `get_device_status(device)` | Returns HEALTHY or DEGRADED with the last event for a device |
| `ping_host(host)` | Returns latency and packet loss (simulated for the demo) |

### Detection rules

| Anomaly | Rule |
|---------|------|
| Link flapping | Same interface goes down 3 or more times |
| Low optical power | `rx_power` below -25 dBm |
| High latency | `HIGH-LATENCY` event logged |
| Packet loss | `PACKET-LOSS` event logged |

Detection is rule-based (deterministic and explainable). The LLM is used for reasoning and explanation on top of the results.

## Setup

### Requirements
- Python 3.10+
- A free Groq API key from [console.groq.com](https://console.groq.com)

### Install and run

```bash
# 1. (Optional) create a virtual environment
python -m venv myenv
myenv\Scripts\activate          # Windows
# source myenv/bin/activate     # Mac/Linux

# 2. Install dependencies
pip install -r requirements.txt

# 3. Generate sample logs
python generate_logs.py

# 4. Set your API key (or paste it in the app sidebar)
set GROQ_API_KEY=gsk_your_key          # Windows CMD
# $env:GROQ_API_KEY="gsk_your_key"     # Windows PowerShell
# export GROQ_API_KEY=gsk_your_key     # Mac/Linux

# 5. Start the app
streamlit run app.py
```

### Changing the model
The default model is `openai/gpt-oss-120b`. Override it without editing code:

```bash
set GROQ_MODEL=openai/gpt-oss-20b
```

Groq retires models from time to time. If you get a `model_not_found` error, check the current list at [console.groq.com/docs/models](https://console.groq.com/docs/models).

```
2026-10-05 09:13:41 optical-mumbai-02 WARN OPTICAL-LOW-POWER port=1/1 rx_power=-27.0dBm threshold=-25dBm
```

The generated logs contain three planted incidents:

| Device | Issue |
|--------|-------|
| `router-delhi-01` | Interface Gi0/1 flapping |
| `optical-mumbai-02` | Receive optical power dropping below threshold |
| `switch-pune-03` | High latency and packet loss on Eth1/4 |

## Limitations

- Logs are synthetic sample data, not a live feed.
- `ping_host` is simulated so the demo does not depend on a real network.
- Anomaly rules use fixed thresholds, with no learning or baselining.
